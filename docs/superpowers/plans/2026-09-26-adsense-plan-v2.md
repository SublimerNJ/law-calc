## 전략 요약

1. **재신청을 멈춘다.** 운영 6개월, 누적 클릭 226에서 재신청하면 같은 판정이 나올 가능성이 높다(원인 1). 같은 계정의 any-calc.dev도 같은 결과였다.
2. **신뢰를 깎는 것부터 없앤다(원인 2).** 법령 오류와 근거 없는 금액은 승인과 무관하게 법률 사이트로서 먼저 고쳐야 한다.
3. **55개를 넓게 고치지 않고, 수요가 확인된 분야를 깊게 만든다(원인 3·4 + 원인 1 대응).** GSC에서 실제로 노출·클릭이 생긴 손해배상·교통사고·상속 쪽을 공공 계산기보다 나은 수준으로 만든다.
4. **꾸준한 운영을 사실로 만든다.** 날짜만 바꾸지 않고, 실제 개정 반영과 신규 글을 주기적으로 쌓는다. 반복 작업은 cron으로 돌린다.

## Global Constraints

- 스크립트나 AI로 여러 페이지 문구를 일괄 생성하지 않는다. 템플릿을 다른 템플릿으로 바꾸지 않는다.
- 법령 수치는 국가법령정보센터 원문(본문+부칙, 시행일)과 한 줄씩 대조한다. 대조하지 않은 항목은 "검증 완료"나 검토일 갱신으로 표시하지 않는다.
- 예시 숫자는 해당 계산 함수 출력과 테스트로 일치시킨다.
- 검토일·sitemap lastmod는 실제로 바뀐 페이지만 바꾼다.
- push, 배포, AdSense 검토 요청, GSC 색인 요청은 매번 사용자 최종 승인 후에만 한다.

### Task A2: 재량 금액 추정 계산기 처리

대상: 보석금, 위자료, 명예훼손, 의료사고, 교통사고 합의금, 부당해고 보상금, 손해배상 일반. 단, 교통사고 합의금·손해배상은 GSC 수요가 있으므로 삭제하지 않는다.

- [ ] 각 계산기의 금액 산출 근거를 코드에서 확인한다. 법정 산식이 있는 부분(일실수입 호프만 계수, 과실상계, 치료비 합산, 부당해고 임금상당액)과 근거 없는 부분(하드코딩 위자료 표, 보석금 표)을 나눈다.
- [ ] 근거 있는 부분만 계산하고, 근거 없는 금액 출력은 없앤다. 그 자리에 요건 체크리스트와 "금액을 좌우하는 요소"를 두고, 공개 판결이나 공식 기준(예: 자동차보험 약관 위자료 기준)을 인용할 수 있을 때만 범위를 보여 준다.
- [ ] 명예훼손 본문과 출력의 모순을 없앤다.
- [ ] 근거 있는 부분이 거의 없는 계산기(보석금 예상)는 체크리스트 도구로 이름·설명을 바꾸거나 가이드로 흡수한다. 결정 내용을 `docs/adsense/tool-triage.md`에 남긴다.
